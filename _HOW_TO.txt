WALLET VERIFICATION BY SIGNATURE (non-custodial)
================================================
Connect a wallet, sign a message, verified. No payment, no transaction,
no private keys. The 0.1 SOL flow stays as the fallback for wallets that
can't connect (hardware, or mobile browsers where connect fails).

1. RUN THE MIGRATION:

FILES
  0013_wallet_signature.sql            <- run in Supabase, don't copy to repo
  lib/siws.ts                          <- NEW  signature checking (server)
  lib/wallet.ts                        <- NEW  wallet detect + sign (client)
  app/api/wallet/connect/route.ts      <- NEW  issues the one-time nonce
  app/api/wallet/signature/route.ts    <- NEW  verifies and marks verified
  components/tabs_VerifyContent.tsx    <- REPLACES  connect buttons + fallback

NO NEW PACKAGES. Signature checking uses Node's built-in crypto, so
there's nothing to install and nothing extra to keep patched.

WHAT THE USER SEES
Verify tab -> "Connect Phantom" (or Solflare/Backpack/Coinbase, whichever
is installed) -> wallet opens showing a plain message that says it proves
ownership and moves no funds -> approve -> verified, balance on the card.
Below that, an OR divider and the old paste-address + 0.1 SOL flow.

MOBILE
If no wallet is detected it tells them to open thesolmates.com inside
their wallet app's browser, which is the reliable path on phones.

WHAT REACHES YOUR SERVER
A public address and a signature. That's all. No key, no seed phrase, no
ability to move anything.

DATABASE
wallets.verified_via is 'signature' or 'payment', so you can tell the two
apart in the admin panel and enforce different rules per platform later.

TEST

  your balance.

- Cancel the wallet prompt -> nothing happens, no error shouted at you.
