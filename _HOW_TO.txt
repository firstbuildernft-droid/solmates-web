LOCATION & DISTANCE
===================

Real location: asks for GPS in onboarding, falls back to rough IP location
if denied, and shows "3 km away" on cards. Raw coordinates are fuzzed and
NEVER sent to the app -- only a rounded distance. This is how Tinder
actually does it.

HOW IT WORKS
- Onboarding: after saving the profile, the browser asks "allow location?"
  Allow  -> real GPS, fuzzed ~500m + rounded, stored server-side.
  Deny   -> falls back to coarse IP location (city-level) so the deck
            still works; card shows city instead of a distance.
- Cards show "3 km away" / "Less than 1 km away", nearest-first.
- Location refreshes silently at most every 6h when you open the deck.
- The real coordinates never leave the server. Only rounded distance does.

TEST
- Fresh account -> onboard -> browser asks for location -> Allow.
- On another account nearby (same city), the card shows a km distance.
- Deny the prompt on a test account -> no distance, still see people.

IMPORTANT: browser location ONLY works on https or localhost. Your Vercel
site is https, so it works there. On localhost it also works. If you ever
open the site by raw IP address, the prompt won't appear -- that's a
browser rule, not a bug.

NOTE ON IP FALLBACK: the x-vercel-ip-* headers only exist on Vercel, not
on localhost. So IP fallback does nothing locally -- test that part on the
deployed site.
